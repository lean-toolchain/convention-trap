## 해결해야 할 결함 (우선순위, 수집 시점 기준 — 1~3, 6은 1차 개선에서 반영)

1. **증인 탐색이 함수·집합 변수 앞에서 멈춘다.** 실제 명제에는 거의 항상 `f : ℕ → ℕ`, `S : ℝ → ℝ → ℝ` 같은 변수가 있다. 지금은 범위 안에 숫자가 아닌 변수가 하나라도 있으면 증인 탐색을 포기해서, `1 / 2`(변수 없음)나 `n / 2` 같은 명백한 경우까지 `unknown`으로 숨는다. → 조건의 변수와 그것에 연결된 가정만 골라 탐색하면 된다. 이것 하나로 7건이 `unknown`에서 경고로 올라올 것으로 본다.
2. **함수 정의 가정을 펼치지 않는다.** miniF2F 618은 `h₀ : ∀ x, p x = x^2 - x + 41`이 있어서 `p`를 대입하면 n = 0 반례가 바로 나오지만, 함수 변수 때문에 반증을 건너뛴다.
3. **"0 때문에 자명해지는" 방향을 못 본다.** `∃ n, …`이 n = 0(또는 ∅, `D = 0`)으로 바로 증명되는 경우가 실제로 많다(FC 7건 이상). 지금의 반증은 "거짓" 방향만 본다. → 존재 명제에 0·∅·1을 넣어 **증명**되는지 시도하는 검사를 추가한다.
4. **전체 함수 junk 값 확장**: `sInf`/`sSup`(ℕ, ℝ), `Set.ncard`/`Nat.card`, `Metric.diam`, `deriv`, 적분, `Real.logb`. 실제 사례 11건 이상. 트랩 카탈로그의 "확장"을 실제 빈도 순으로 당긴다.
5. **명제가 쓰는 Prop이 아닌 정의 본문을 보지 않는다.** FC #5668은 `def A (x : ℝ) : ℝ := ((1/2 * card : ℕ) : ℝ)` 안에 함정이 있다. statement-reading-set과 연결할 부분.
6. **CI 전술에 비선형 처리 추가**: `x ≤ x ^ 2`(ℕ)를 증명하지 못해 수정된 명제(neg_mf618)에도 `unknown`이 남는다. `nlinarith`/`positivity` 조합을 CI에 추가.
7. 타입 추론(`∃ c > 0`이 ℕ), Pi 순서, `Fin` 순환, `↔` 안의 가드는 junk 값이 아니지만 실제로 반복되는 관례 함정이다. 별도 종류로 둘지 결정이 필요하다.

## 한계

- FC 이슈 분류는 제목 기준이다. 본문을 다 읽고 두 사람이 라벨링한 것이 아니다.
- `[model]` 재현은 원래 정의를 단순화했다. 특히 결론을 단순화한 것은 반증(오류) 결과가 의미 없을 수 있다(예: `neg_fc6479`의 natZero 오류는 모델 때문에 생긴 것).
- 수정 전후 커밋에서 원본 툴체인으로 직접 돌린 것이 아니라, 현재 Mathlib(v4.36.0)으로 옮겨 적은 것이다.
